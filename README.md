# Экспертная лаборатория

Учебная игра по теории судебной экспертизы КР (лекции 2–3). Статический фронтенд на GitHub Pages + Google Apps Script как бэкенд, Google Таблица как хранилище. Без сборки и зависимостей: нативные ES-модули.

## Структура

```
index.html              оболочка, подключает css/app.css и js/main.js
css/app.css             стили (светлая и тёмная тема)
data/cases.json         база дел — единственный источник вопросов (правильный ответ всегда options[0])
js/
  config.js             правила игры (время, число дел, баллы) и версии протокола
  main.js               загрузка базы дел, регистрация маршрутов, досылка очереди
  router.js             hash-маршрутизатор: view(ctx) → cleanup
  core/                 логика без DOM
    game.js             чистые функции проверки: createSession / answer / next / totals
    scoring.js          баллы и звания (дублируется в server/Code.gs → Score_)
    session.js          сохранение незаконченной игры (продолжение после перезагрузки)
    api.js              транспорт к Apps Script, ApiError с кодами, очередь outbox
    demo-server.js      тот же протокол в localStorage — демо-режим без таблицы
    bank.js             загрузка и проверка data/cases.json
    identity.js         нормализация имени/группы, ключ игрока
    ranking.js          лучшая попытка на игрока, сортировка
    storage.js          localStorage с пространством имён и миграцией со старой версии
  ui/                   dom.js (экранирующий шаблонизатор html``), characters.js (SVG-персонажи), components.js
  views/                экраны: home, play, result, rating, admin/{index,dashboard,ceremony,stats,state}
server/Code.gs          бэкенд для Apps Script (в репозитории — для истории; копия лежит в инструкции)
```

## Маршруты

`#/` главная · `#/play` дело · `#/result` итог · `#/rating` рейтинг · `#/admin` кабинет · `#/admin/results` пьедестал. Старый адрес `#admin` тоже работает. Таблица задаётся параметром `?lab=<id Apps Script>` и запоминается.

## Протокол

`POST` на URL веб-приложения, тело — JSON `{ action, ...}` (Content-Type text/plain, чтобы не было CORS preflight). Ответ: `{ ok: true, version, ... }` или `{ ok: false, version, code, error }`.

| action | доступ | что делает |
|---|---|---|
| `ping` | все | проверка связи и версии |
| `start` | все | проверяет лимит попыток, выдаёт `attemptId` и случайную колоду id |
| `finish` | все | принимает `[{id, choice, ms}]`, **сам** считает баллы, возвращает итог |
| `top` | все | завершённые попытки без ответов |
| `login` | все | пароль → токен (HMAC, 30 дней); первый вход задаёт пароль; сохраняет адрес сайта |
| `list` / `grant` / `grantAll` / `logoutAll` | токен | данные кабинета и выдача попыток |

Коды ошибок: `NETWORK`, `OUTDATED`, `BLOCKED`, `AUTH`, `BAD_PASSWORD`, `RATE`, `NO_BANK`, `NOT_FOUND`, `BAD_ANSWERS`.

## Честность результатов

- Колоду выдаёт сервер и запоминает её; ответы на другие дела не примутся.
- Баллы считает сервер по выбранным вариантам. Подделать итоговое число нельзя.
- Время ответа сообщает клиент, поэтому бонус ограничен: быстрее 2 с он не растёт. Общее время попытки сервер меряет сам.
- Попытка создаётся при старте, поэтому перезагрузка или новая вкладка не дают новый набор дел. Незаконченная игра продолжается с того же дела, таймер не сбрасывается.
- Ограничение: ключ игрока — фамилия, имя и группа. Сменив имя, можно сыграть ещё раз; такие записи видны в кабинете. Правильные ответы лежат в `data/cases.json`, и настойчивый человек может их прочитать. Для учебной игры это приемлемо.

## Пароль руководителя

Хранится в свойствах скрипта как соль + SHA-256. В браузере остаётся только токен. После 10 неверных вводов вход блокируется на 10 минут. «Выйти на всех устройствах» меняет секрет подписи. Сброс пароля — функция `resetPassword` в редакторе Apps Script.

## Локальный запуск

```
python3 -m http.server 8000
```

Затем откройте http://localhost:8000. Без `?lab=` игра работает в демо-режиме: данные остаются в браузере. Открыть `index.html` двойным щелчком нельзя — ES-модули не работают по `file://`.

## Добавить или изменить дела

Отредактируйте `data/cases.json`. Правильный вариант всегда идёт первым, в игре варианты перемешиваются. Новым делам давайте новые `id`, а существующие не меняйте: на них завязана статистика. Сервер обновляет список дел раз в 10 минут.
